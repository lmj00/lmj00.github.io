### 개요
Prometheus는 메트릭 기반의 오픈소스 모니터링 시스템이다. 이 시스템은 **시계열 데이터**를 수집, 저장, 쿼리하고, 규칙에 따라 **알림**을 생성하는 일련의 컴포넌트들로 구성된다. 효과적인 모니터링을 구축하려면 데이터가 어디서 생성되고, 어떻게 수집되며, 어떤 경로를 통해 처리되는지 이해하는 것이 필수적이다. 이 글은 Prometheus 공식 문서의 용어집을 바탕으로, 시스템의 핵심 개념과 구성 요소를 체계적으로 설명한다.

### 핵심 구성 요소와 데이터 흐름
Prometheus 시스템의 핵심은 **Prometheus** 서버 자체다. 이는 시스템 전체를 지칭하기도 하지만, 보통 메트릭을 **풀(Pull)** 방식으로 수집(Scrape)하고, 저장하며, **PromQL**로 쿼리하는 주 바이너리를 의미한다.

데이터 수집의 출발점은 **메트릭을 노출(Expose)** 하는 곳이다. 크게 두 가지 방식이 있다.
*   **직접 계측(Direct instrumentation)**: 애플리케이션 소스 코드 내에 **클라이언트 라이브러리**(Go, Java, Python, Ruby 등)를 사용해 메트릭을 추가하는 방식이다. 이렇게 계측된 코드는 실행 시 메트릭을 HTTP 엔드포인트로 노출한다.
*   **익스포터(Exporter)**: Prometheus 형식을 지원하지 않는 기존 시스템(예: 데이터베이스, 하드웨어)에서 메트릭을 수집하기 위해 실행되는 별도의 바이너리다. 익스포터는 원본 시스템의 메트릭을 조회해 Prometheus가 이해할 수 있는 형식으로 변환하여 노출한다. 익스포터 내에서 실제 메트릭 집합을 정의하는 단위를 **컬렉터(Collector)** 라고 한다.

Prometheus가 메트릭을 수집하는 단위는 **타겟(Target)** 이다. 타겟은 스크랩할 객체의 정의(라벨, 인증 정보 등)를 의미한다. 비슷한 목적을 가진 타겟들의 집합은 **잡(Job)** 으로 묶이며, 잡 내에서 각 타겟을 고유하게 식별하는 라벨이 **인스턴스(Instance)** 다. 메트릭이 노출되는 지점, 즉 일반적으로 단일 프로세스에 해당하는 스크랩 소스를 **엔드포인트(Endpoint)** 라고 한다.

### 데이터 모델: 시계열, 샘플, 라벨
Prometheus는 모든 데이터를 **시계열(Time Series)** 로 저장한다. 시계열은 동일한 메트릭과 동일한 라벨 집합에 속하는, 타임스탬프가 붙은 값들의 흐름이다. 이 흐름에서 특정 시점의 단일 값(부동소수점 값과 밀리초 정밀도의 타임스탬프로 구성)을 **샘플(Sample)** 이라고 한다.

### 특수 목적 컴포넌트
*   **Pushgateway**: 배치 잡처럼 일시적으로 실행되어 종료되는 작업의 메트릭을 수집하기 위해 사용된다. 잡은 메트릭을 Pushgateway로 푸시하고, Prometheus는 Pushgateway에서 해당 메트릭을 스크랩한다.
*   **브리지(Bridge)**: 클라이언트 라이브러리에서 샘플을 가져와 Graphite와 같은 비 Prometheus 모니터링 시스템으로 메트릭을 내보내는 컴포넌트다. 익스포터와 반대 방향의 변환을 담당한다.

### 원격 저장 및 연동
대규모 또는 장기 데이터 저장을 위해 **원격 읽기(Remote Read)** 와 **원격 쓰기(Remote Write)** 기능을 사용한다.
*   **원격 쓰기**: Prometheus가 수집한 샘플을 실시간으로 장기 저장소 같은 외부 시스템으로 전송한다. 전송 대상은 **원격 쓰기 엔드포인트**다.
*   **원격 읽기**: Prometheus가 쿼리를 실행할 때, 장기 저장소 같은 외부 시스템의 시계열 데이터를 투명하게 읽을 수 있게 한다. 읽기 대상은 **원격 읽기 엔드포인트**다.

이때 외부 시스템이 해당 프로토콜을 직접 지원하지 않으면, **원격 쓰기 어댑터** 또는 **원격 읽기 어댑터**가 중간에서 데이터 형식을 변환하는 역할을 한다.

### 규칙, 알림 및 시각화
*   **레코딩 규칙(Recording Rules)**: 자주 필요하거나 계산 비용이 높은 PromQL 표현식을 미리 계산하여 그 결과를 새로운 시계열로 저장한다. 이는 쿼리 성능을 최적화한다.
*   **알림(Alert)**: Prometheus 내의 알림 규칙이 활성화되어 발생한 결과다. 발생한 알림은 **Alertmanager**로 전송된다.
*   **Alertmanager**: Prometheus에서 받은 알림을 그룹화, 중복 제거, **사일런스(Silence)** 적용, 스로틀링 처리한 후, **노티피케이션(Notification)** 으로 묶어 이메일, PagerDuty, Slack 등으로 발송한다. 사일런스는 특정 라벨과 일치하는 알림이 노티피케이션에 포함되지 않도록 차단한다.
*   **믹스인(Mixin)**: 특정 컴포넌트나 시스템을 위한 재사용 및 확장 가능한 Prometheus 알림, 레코딩 규칙, Grafana 대시보드 세트다. Jsonnet으로 패키징되어 표준화된 모니터링 구성을 가능하게 한다.
*   **PromQL**: Prometheus의 강력한 쿼리 언어로, 집계, 데이터 분할, 예측, 조인 등 다양한 연산을 지원한다.
*   **Grafana**: Prometheus의 기본 대시보드 빌더였던 **Promdash**를 대체한 시각화 도구다.

### 주요 용어 비교 및 정리
| 용어 | 핵심 역할 | 관련 컴포넌트/개념 |
| :--- | :--- | :--- |
| **직접 계측** | 애플리케이션 코드 내부에 메트릭 추가 | 클라이언트 라이브러리 |
| **익스포터** | 외부 시스템 메트릭을 Prometheus 형식으로 변환 노출 | 컬렉터 |
| **타겟** | 스크랩 대상 객체의 정의 (설정) | 잡, 인스턴스, 엔드포인트 |
| **시계열** | 동일 메트릭/라벨의 타임스탬프 값 흐름 (저장 단위) | 샘플 |
| **레코딩 규칙** | 고비용 쿼리 결과를 미리 계산/저장 (성능 최적화) | PromQL |
| **알림** | 규칙 조건 충족 시 발생하는 이벤트 | Alertmanager, 노티피케이션 |
| **원격 쓰기/읽기** | 실시간 샘플 전송 / 외부 저장소 데이터 조회 | 원격 엔드포인트, 어댑터 |

### 정리
Prometheus 모니터링은 **풀 기반 수집**과 **다차원 시계열 데이터 모델**을 근간으로 한다. **직접 계측**과 **익스포터**를 통해 메트릭을 노출시키고, **타겟**으로 정의해 수집한다. 수집된 데이터는 **PromQL**로 유연하게 쿼리 및 집계되며, **레코딩 규칙**으로 성능을 개선할 수 있다. **Alertmanager**는 알림을 지능적으로 관리하고, **원격 읽기/쓰기**를 통해 저장소를 확장한다. 이러한 컴포넌트들이 조화를 이루어 종합적인 모니터링 파이프라인을 구성한다.
