### 개요
**로케일(Locale)** 지원은 애플리케이션이 알파벳, 정렬 순서, 숫자 형식 등 **문화적 선호도**를 존중하는 것을 의미한다. PostgreSQL은 서버 운영체제가 제공하는 표준 ISO C 및 POSIX 로케일 기능을 사용한다. 이 기능은 데이터 정렬, 대소문자 변환, 패턴 매칭, 메시지 언어 등 다양한 SQL 동작에 영향을 미치며, 데이터베이스의 **글로벌 사용성**을 높이는 데 핵심적이다. 그러나 잘못 설정하거나 변경하면 성능 저하나 인덱스 손상과 같은 문제를 초래할 수 있으므로 그 동작 원리를 이해하는 것이 중요하다.

### 로케일의 개념과 범주
로케일은 단일한 설정이 아니라, **여러 하위 범주**로 나누어 제어할 수 있다. 각 범주는 지역화 규칙의 특정 측면만을 담당한다.

| 범주 | 설명 |
| :--- | :--- |
| **LC_COLLATE** | 문자열의 **정렬 순서**를 결정한다. |
| **LC_CTYPE** | 문자 분류(무엇이 글자인지, 대문자 변환은 무엇인지)를 결정한다. |
| **LC_MESSAGES** | 시스템 메시지의 **언어**를 결정한다. |
| **LC_MONETARY** | **통화 금액**의 형식을 결정한다. |
| **LC_NUMERIC** | **숫자**의 형식(예: 소수점 구분자)을 결정한다. |
| **LC_TIME** | **날짜와 시간**의 형식을 결정한다. |

이러한 범주들은 서로 다른 로케일 규칙을 혼합하여 사용할 수 있게 해준다. 예를 들어, 영어 정렬 규칙을 사용하되 메시지는 스페인어로 출력하도록 설정하는 것이 가능하다.

### 로케일 설정의 계층 구조와 방법
로케일 설정은 **계층적**으로 적용되며, 더 세부적인 수준에서 상위의 기본값을 재정의할 수 있다. 설정 범위는 다음과 같다.

1.  **운영체제 환경**: 새로 초기화되는 데이터베이스 클러스터의 로케일 기본값을 제공한다. 대부분의 경우 이 설정만으로 충분하다.
2.  **데이터베이스 클러스터 초기화 (`initdb`)**: `--locale` 옵션을 사용하여 클러스터 전체의 기본 로케일을 명시적으로 지정한다. 특정 범주만 재정의하려면 `--lc-collate`, `--lc-monetary` 등의 옵션을 사용한다.
    ```bash
    initdb --locale=fr_CA --lc-monetary=en_US
    ```
3.  **개별 데이터베이스 (`CREATE DATABASE`)**: 하나의 클러스터 내에서 테넌트별로 다른 로케일 요구사항이 있다면 데이터베이스 생성 시 로케일을 별도로 지정할 수 있다.
4.  **개별 테이블 컬럼 (Collation 객체)**: `LC_COLLATE`와 `LC_CTYPE`의 영향을 받는 정렬 순서를 컬럼 단위로 지정할 수 있다. 이는 **Collation**이라는 SQL 객체를 통해 이루어진다.
5.  **개별 쿼리 (Collation 객체)**: 실행 시점의 선택이나 임시 실험을 위해 쿼리 수준에서 정렬 규칙을 변경할 수 있다.

### 로케일 제공자(Locale Provider)
로케일 제공자는 **Collation과 문자 분류 동작을 정의하는 라이브러리**를 지정한다. 각 설정 단계(예: `initdb`, `CREATE DATABASE`, Collation 생성)에서 제공자를 선택할 수 있으며, 서로 다른 제공자를 혼합하여 사용할 수 있다.

| 제공자 | 설명 | 주요 특징 |
| :--- | :--- | :--- |
| **`builtin`** | PostgreSQL 내장 연산을 사용한다. | `C`, `C.UTF-8`, `PG_UNICODE_FAST` 로케일만 지원. 데이터베이스 인코딩(`UTF-8`)에 의존적. |
| **`icu`** | 외부 **ICU(International Components for Unicode)** 라이브러리를 사용한다. | 운영체제와 데이터베이스 인코딩에 **독립적**인 동작 제공. `LC_COLLATE`와 `LC_CTYPE`을 독립적으로 설정 가능. 결과는 ICU 라이브러리 버전에 영향을 받을 수 있음. |
| **`libc`** | 운영체제의 **C 라이브러리**를 사용한다. | `LC_COLLATE`와 `LC_CTYPE` 설정에 의해 동작이 통제되므로, 두 값을 독립적으로 설정할 수 없음. 동일한 로케일 이름이라도 플랫폼에 따라 다르게 동작할 수 있음. |

ICU 제공자를 사용할 때는 **언어 태그(Language Tag)** 형식(예: `en-US`, `fr-CA`)으로 로케일을 지정한다. 또한 `-u-kn-true`와 같은 접미사를 추가하여 **대소문자 구분 무시**와 같은 맞춤형 정렬 설정을 포함할 수 있다.

### 로케일이 SQL 동작에 미치는 영향
로케일 설정은 다음과 같은 PostgreSQL 기능에 직접적인 영향을 미친다.
*   **텍스트 데이터 정렬**: `ORDER BY` 및 비교 연산자.
*   **문자열 함수**: `upper`, `lower`, `initcap`.
*   **패턴 매칭**: `LIKE`, `SIMILAR TO`, 정규 표현식(대소문자 무시 매칭 및 문자 클래스 분류에 영향).
*   **형식화 함수**: `to_char` 계열 함수.
*   **인덱스 사용**: `LIKE` 절이 인덱스를 사용할 수 있는지 여부.

### 중요한 제약사항과 주의점
1.  **고정된 로케일 범주**: `LC_COLLATE`와 `LC_CTYPE`은 **데이터베이스 생성 시 결정되며 이후 변경할 수 없다**. 이들은 텍스트 컬럼 인덱스의 정렬 순서에 영향을 미치기 때문이다. 변경 시 인덱스가 손상될 수 있다. (Collation 객체를 사용하면 이 제한을 완화할 수 있다.)
2.  **성능 영향**: `C` 또는 `POSIX` 이외의 로케일을 사용하면 **문자 처리 속도가 느려지고**, `LIKE` 절이 일반 인덱스를 사용하지 못하게 될 수 있다. 실제로 필요할 때만 로케일을 사용하는 것이 좋다.
3.  **서버 환경 기준**: 로케일 동작은 **클라이언트 환경이 아닌 서버의 환경 변수**에 의해 결정된다. 따라서 서버를 시작하기 전에 올바른 로케일 설정을 구성해야 한다. 클라이언트와 서버 로케일이 다르면 메시지 언어가 달라질 수 있다.
4.  **메시지 번역(NLS)**: 메시지가 사용자 선호 언어로 번역되려면, PostgreSQL 빌드 시 `--enable-nls` 옵션이 활성화되어 있어야 한다.

### 로케일 문제 해결
로케일이 예상대로 동작하지 않는다면 다음을 확인해야 한다.
*   운영체제의 로케일 지원이 올바르게 구성되었는지 확인 (`locale -a` 명령어로 설치된 로케일 목록 확인).
*   PostgreSQL이 실제로 어떤 로케일을 사용하고 있는지 `SHOW` 명령어로 확인.
*   서버 측 오류 메시지를 파싱하는 클라이언트 애플리케이션은 서버 메시지 언어가 다르면 문제가 발생할 수 있으므로, **오류 코드 체계**를 활용하는 것이 좋다.

### 정리
*   로케일은 문화적 형식을 지원하는 기능으로, **정렬, 문자 분류, 메시지, 숫자/통화/시간 형식** 등 다양한 범주로 나뉜다.
*   설정은 **운영체제 → 클러스터 → 데이터베이스 → 컬럼 → 쿼리** 순으로 계층적이며, 세부 수준에서 재정의 가능하다.
*   **`LC_COLLATE`와 `LC_CTYPE`은 데이터베이스 생성 시 고정**되어 인덱스 정렬에 영향을 주므로 신중히 선택해야 한다.
*   **`icu`, `libc`, `builtin`** 세 가지 로케일 제공자 중 선택할 수 있으며, ICU는 플랫폼 독립적 동작을 제공한다.
*   로케일 사용은 **성능 저하**를 초래할 수 있으므로 필요한 경우에만 사용하고, `C` 로케일과의 성능 차이를 인지해야 한다.
