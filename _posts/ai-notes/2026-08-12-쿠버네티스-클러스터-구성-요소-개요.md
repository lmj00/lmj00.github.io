> 한 줄 요약: 쿠버네티스 클러스터는 **컨트롤 플레인**과 **워커 노드**로 구성되며, 각각의 핵심 컴포넌트들이 클러스터의 상태 관리와 컨테이너 실행을 담당한다.

### 개요
쿠버네티스 클러스터는 여러 컴포넌트가 조화를 이루어 동작하는 분산 시스템이다. 이 아키텍처는 소규모 개발 환경부터 대규모 프로덕션 배포까지 다양한 요구사항에 적응할 수 있도록 유연성을 제공한다. 본 글에서는 클러스터를 구성하는 핵심 요소들의 역할과 관계를 개념적으로 살펴본다.

### 클러스터의 기본 구조
쿠버네티스 클러스터는 크게 두 부분으로 나뉜다: **컨트롤 플레인**과 하나 이상의 **워커 노드**. 컨트롤 플레인은 클러스터의 전반적인 상태를 관리하는 두뇌 역할을 하며, 워커 노드는 실제 애플리케이션 워크로드(파드)를 실행하는 근육 역할을 한다.

### 컨트롤 플레인 컴포넌트
컨트롤 플레인은 클러스터의 중앙 관리 시스템으로, 다음 네 가지(또는 다섯 가지) 핵심 서버 컴포넌트로 이루어진다.

**kube-apiserver**
쿠버네티스 HTTP API를 외부에 노출하는 핵심 컴포넌트 서버다. 모든 관리 명령과 상태 조회 요청은 이 API 서버를 통해 이루어진다.

**etcd**
모든 API 서버 데이터를 위한 일관되고 고가용성의 키-값 저장소다. 클러스터의 구성, 상태, 메타데이터 등 모든 중요한 데이터가 이곳에 저장된다.

**kube-scheduler**
아직 노드에 할당되지 않은 새로 생성된 파드를 감시하고, 각 파드를 실행하기에 적합한 워커 노드를 선택하여 할당하는 역할을 한다.

**kube-controller-manager**
쿠버네티스 API의 동작을 구현하는 **컨트롤러**들을 실행한다. 컨트롤러는 실제 시스템 상태가 원하는 상태(예: 복제본 수)와 일치하도록 지속적으로 조정하는 루프를 실행한다.

**cloud-controller-manager** (선택사항)
기반 클라우드 공급자의 서비스(예: 로드 밸런서, 스토리지 볼륨)와 쿠버네티스를 통합하는 컴포넌트다. 특정 클라우드 환경에서만 필요하다.

### 노드 컴포넌트
이 컴포넌트들은 모든 워커 노드에서 실행되며, 파드를 구동하고 쿠버네티스 런타임 환경을 제공한다.

**kubelet**
노드에 할당된 파드들이 정상적으로 실행되도록 보장하는 에이전트다. 파드 명세에 정의된 컨테이너들이 실행 중인지 관리한다.

**kube-proxy** (선택사항)
노드의 네트워크 규칙을 유지관리하여 쿠버네티스 **서비스**의 개념(예: 파드에 대한 네트워크 트래픽 로드 밸런싱)을 구현한다.

**컨테이너 런타임**
컨테이너를 실제로 실행하는 소프트웨어다(예: containerd, CRI-O). 쿠버네티스 자체의 일부가 아닌 제3자 프로젝트다.

노드에는 쿠버네티스 컴포넌트 외에도 추가 소프트웨어가 필요할 수 있다. 예를 들어, Linux 노드에서는 로컬 컴포넌트들을 감시하기 위해 `systemd`를 실행할 수 있다.

### 애드온
애드온은 쿠버네티스의 기능을 확장하는 클러스터 수준의 서비스다. 주요 예시는 다음과 같다.
*   **DNS**: 클러스터 전체에 걸친 DNS 이름 해결을 제공한다.
*   **웹 UI (대시보드)**: 웹 인터페이스를 통한 클러스터 관리 기능을 제공한다.
*   **컨테이너 리소스 모니터링**: 컨테이너 메트릭을 수집하고 저장한다.
*   **클러스터-레벨 로깅**: 컨테이너 로그를 중앙 로그 저장소에 저장한다.

### 정리
1.  쿠버네티스 클러스터는 관리부(**컨트롤 플레인**)와 실행부(**워커 노드**)로 분리된 아키텍처를 가진다.
2.  컨트롤 플레인의 핵심은 API 서버(`kube-apiserver`), 상태 저장소(`etcd`), 스케줄러, 컨트롤러 매니저다.
3.  모든 노드에는 파드 생명주기를 관리하는 `kubelet`과 컨테이너를 실행하는 **컨테이너 런타임**이 필수적으로 동작한다.
4.  네트워크 프록시(`kube-proxy`)나 클라우드 통합 매니저와 같은 컴포넌트는 환경에 따라 선택적으로 사용된다.
5.  DNS, 모니터링, 로깅 같은 추가 기능은 **애드온**을 통해 클러스터에 배포하여 확장할 수 있다.
