#### 컨트롤 플레인 보호
클러스터 보안의 핵심은 **쿠버네티스 API에 대한 접근 제어**다. 이를 위해 다음과 같은 기법이 사용된다.
- **전송 중 데이터 암호화**: 컨트롤 플레인 내부 및 컨트롤 플레인과 클라이언트 간 통신에는 TLS를 구성하여 사용한다.
- **저장 데이터 암호화**: 쿠버네티스 컨트롤 플레인 내에 저장된 데이터를 위한 **저장 데이터 암호화**를 활성화할 수 있다. 이는 사용자 워크로드 데이터의 저장 암호화와는 별개의 개념이다.

#### 워크로드 및 데이터 보호
실제 애플리케이션(파드)과 민감한 설정값을 보호하는 메커니즘이다.
- **Pod Security Standards**: 파드와 그 컨테이너가 적절히 격리되도록 보장하는 표준을 적용한다. 더 커스텀한 격리가 필요하면 `RuntimeClasses`를 정의하여 사용할 수 있다.
- **Secret API**: 기밀성이 요구되는 구성 값에 대한 기본적인 보호를 제공한다.
- **Network Policies**: 파드 간, 또는 파드와 클러스터 외부 네트워크 간의 트래픽 흐름을 제어할 수 있다.
- **생태계 보안 제어**: 쿠버네티스 생태계의 다른 프로젝트들을 활용하여 파드, 컨테이너, 실행 이미지에 대한 예방적 또는 탐지적 제어를 구현할 수 있다.

#### 정책 및 접근 통제
API 요청 수준에서 보안을 강화하는 메커니즘이다.
- **Admission Controllers**: 쿠버네티스 API 요청을 가로채서 요청의 특정 필드를 기반으로 검증하거나 변경할 수 있는 플러그인이다. 이를 신중하게 설계하면 쿠버네티스 API가 버전 업데이트를 거치며 변경될 때 의도치 않은 중단을 피하는 데 도움이 된다.
- **정책 정의**: `NetworkPolicy`(네트워크 패킷 필터링에 대한 선언적 제어)나 `ValidatingAdmissionPolicy`(쿠버네티스 API를 통해 누군가가 할 수 있는 변경 사항에 대한 선언적 제한)와 같은 쿠버네티스 네이티브 메커니즘으로 보안 정책을 정의할 수 있다. 또한, 확장 메커니즘을 통해 소스 코드 검토, 컨테이너 이미지 승인, API 접근 제어 등에 대한 정책을 구현하는 생태계 프로젝트들을 활용할 수도 있다.
