### 개요
UDP(User Datagram Protocol)는 상호 연결된 컴퓨터 네트워크 환경에서 패킷 교환 방식의 통신을 위한 **데이터그램 모드**를 제공하는 프로토콜이다. 이 프로토콜은 IP(Internet Protocol)를 기반으로 동작하며, **TCP와 달리 신뢰성 있는 순차적 데이터 전송을 보장하지 않는다.** 대신 최소한의 프로토콜 메커니즘으로 애플리케이션 프로그램이 다른 프로그램으로 메시지를 보낼 수 있는 절차를 제공하는 것이 주된 목적이다.

### 포맷과 필드
UDP 헤더는 **8옥텟의 고정 크기**와 선택적 데이터 영역으로 구성된다. 구조는 다음과 같다.

![diagram](/assets/diagrams/2026-08-30-udp의-구조와-특성-1.svg)

주요 필드는 다음과 같다.

| 필드 | 설명 |
| :--- | :--- |
| **소스 포트 (Source Port)** | 선택적 필드. 의미가 있을 경우 송신 프로세스의 포트를 나타내며, 응답을 보낼 기본 포트로 간주될 수 있다. 사용되지 않으면 0이 삽입된다. |
| **목적지 포트 (Destination Port)** | 특정 인터넷 목적지 주소 내에서 의미를 갖는 수신 포트이다. |
| **길이 (Length)** | UDP 헤더와 데이터를 포함한 전체 사용자 데이터그램의 **옥텟 단위 길이**. 최소값은 헤더만 있는 8이다. |
| **체크섬 (Checksum)** | 오류 검사를 위한 16비트 **1의 보수 합(one's complement sum)**. IP 헤더의 정보, UDP 헤더, 데이터로 구성된 **의사 헤더(pseudo header)**를 기반으로 계산된다. |

**의사 헤더**는 UDP 헤더 앞에 개념적으로 붙는 것으로, **출발지 주소, 목적지 주소, 프로토콜 번호, UDP 길이**를 포함한다. 이는 잘못 라우팅된 데이터그램으로부터의 보호를 제공한다. 계산된 체크섬이 0이면 모든 비트가 1(0xFFFF)인 값으로 전송되며, 전송된 체크섬 값이 모두 0인 경우는 송신측에서 체크섬을 생성하지 않았음을 의미한다(디버깅이나 상위 계층 프로토콜이 무시하는 경우).

### 작동 방식과 인터페이스
UDP는 **트랜잭션 지향(transaction oriented)** 프로토콜로, 각 데이터그램 전송이 독립적이다. 공식 문서는 사용자 인터페이스가 다음 세 가지 작업을 허용해야 한다고 설명한다.
*   새로운 수신 포트 생성
*   수신 포트에 대한 수신 작업 수행 (데이터 옥텟과 출발지 포트, 출발지 주소 정보 반환)
*   데이터, 출발지/목적지 포트 및 주소를 지정하여 데이터그램을 보내는 작업

IP 인터페이스 측면에서 UDP 모듈은 인터넷 헤더로부터 **출발지 및 목적지 인터넷 주소와 프로토콜 필드**를 확인할 수 있어야 한다. 한 가지 가능한 인터페이스 방식은 수신 작업에 대해 전체 인터넷 데이터그램(인터넷 헤더 포함)을 반환하고, 송신 시에는 헤더가 완전히 구성된 전체 인터넷 데이터그램을 IP에 전달하는 것이다. 그러면 IP는 일관성을 위해 특정 필드를 검증하고 인터넷 헤더 체크섬을 계산한다.

### 프로토콜 특성과 용도
UDP의 핵심 특성은 **전달 보장과 중복 방지가 없다는 것**이다. 따라서 신뢰성 있고 순서가 정렬된 스트림 데이터 전송이 필요한 애플리케이션은 TCP를 사용해야 한다. UDP는 프로토콜 오버헤드가 적어 빠른 전송이 중요한 경우에 적합하다.

RFC 768에서 언급된 UDP의 주요 용도는 **인터넷 이름 서버(Internet Name Server)**와 **간단한 파일 전송 프로토콜(Trivial File Transfer)**이다. 또한, UDP는 인터넷 프로토콜(IP) 계층에서 사용될 때 프로토콜 번호 **17(10진수)**로 식별된다.

### 정리
UDP는 IP를 기반으로 한 단순하고 가벼운 전송 계층 프로토콜이다. 고정된 8바이트 헤더와 의사 헤더를 이용한 체크섬으로 기본적인 오류 검출을 지원하지만, 연결 설정 없이 독립적인 데이터그램을 전송하는 방식이므로 신뢰성과 순서 보장은 애플리케이션의 책임이다. DNS 조회나 TFTP와 같이 빠른 요청-응답이 중요하거나, 오버헤드를 최소화해야 하는 통신에 주로 활용된다.
