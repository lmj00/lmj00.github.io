### 개요
**Character Generator Protocol(약어 CHARGEN)**은 1983년에 제정된 **RFC 864**로 정의된 네트워크 진단 및 측정용 프로토콜이다. 이 프로토콜의 핵심 목적은 서버가 클라이언트의 입력을 무시하고 계속해서 문자 데이터 스트림을 생성하여 보내는 데 있다. 이를 통해 네트워크 연결 상태, 대역폭, 처리량, 또는 프로토콜 스택의 동작을 테스트하는 유틸리티로 사용된다. TCP와 UDP 두 가지 전송 계층 프로토콜을 모두 지원하며, 각각 **포트 19**를 사용한다.

### 프로토콜 작동 방식
RFC 864는 동일한 서비스의 논리를 TCP와 UDP 두 가지 방식으로 구현한다. 공통점은 **클라이언트가 보내는 데이터(요청 내용)를 완전히 무시한다**는 것이다. 서버의 응답은 자체적으로 생성된 패턴에만 의존한다.

#### TCP 기반 서비스
TCP 버전은 **연결 지향적**으로 동작한다. 서버는 TCP 포트 19에서 연결 요청을 기다린다. 일단 TCP 연결이 수립되면, 서버는 **연결을 통해 지속적으로 데이터 스트림을 보내기 시작한다**. 이때 클라이언트가 보내는 어떠한 데이터도 버린다. 이 데이터 전송은 **클라이언트가 연결을 종료할 때까지** 계속된다.

RFC는 사용자가 이 서비스를 이용하다가 갑자기 연결을 정상 종료(`close`)하지 않고 강제로 중단(`abort`)할 가능성이 높음을 지적하며, 서버 구현 시 두 경우 모두를 처리할 수 있어야 함을 강조한다. 데이터 흐름은 TCP의 **내재된 흐름 제어(flow control) 메커니즘**에 의해 자연스럽게 조절되므로, 서버가 클라이언트의 처리 능력보다 빠르게 데이터를 보내는 문제는 발생하지 않는다.

#### UDP 기반 서비스
UDP 버전은 **비연결형, 상태 비저장(stateless)** 방식으로 동작한다. 서버는 UDP 포트 19에서 데이터그램을 기다린다. 클라이언트로부터 **단 하나의 데이터그램**이 수신되면, 서버는 그에 대한 응답으로 **단 하나의 데이터그램**을 보낸다. 이 응답 데이터그램에는 **0개에서 512개 사이의 임의 개수의 문자**가 포함된다. UDP 서비스에는 상태 정보가 유지되지 않으므로, 연속된 응답 데이터그램 사이에 데이터의 연속성은 없다. TCP와 마찬가지로 요청-응답이 1:1로 제한되므로 데이터 과부하 문제는 없다.

### 데이터 형식과 권장 패턴
RFC는 전송되는 **데이터의 내용에 대해 엄격한 제한을 두지 않는다**. "데이터는 무엇이든 될 수 있다"고 명시한다. 그러나 **인식 가능한 패턴**을 사용할 것을 권장하며, 가장 대중적인 패턴을 예시로 제시한다.

권장 패턴은 **72자 길이의 라인**으로 구성되며, 각 라인은 ASCII 출력 가능 문자(공백 제외, 총 95자)로 채워진다. 이 95개의 문자를 원형 순열처럼 생각하여(`0`번 문자 다음이 `94`번 문자), 라인마다 한 칸씩 이동시키는 방식으로 데이터를 생성한다.

1. ASCII 출력 가능 문자(33-126) 95개를 정렬하여 `0`부터 `94`까지 번호를 매긴다.
2. 0번 라인에는 문자 `0`부터 `71`까지(72자)를 놓는다.
3. 1번 라인에는 문자 `1`부터 `72`까지를 놓는다.
4. 일반화하면, **N번 라인**에는 `(0+N) mod 95` 번호의 문자부터 `(71+N) mod 95` 번호의 문자까지를 놓는다.
5. 각 라인은 **캐리지 리턴(CR)**과 **라인 피드(LF)**로 끝난다.

이 알고리즘에 따라 생성된 데이터는 문서에 제시된 예제처럼, 라인마다 문자가 한 칸씩 쉬프트되어 보여지는 규칙적인 패턴을 가진다. 이 패턴은 네트워크 전송 중 데이터 손실이나 재배열이 발생했는지를 쉽게 눈으로 확인할 수 있게 해주는 진단적 가치를 지닌다.

### 프로토콜의 특성과 한계
CHARGEN 프로토콜은 단순함 그 자체가 장점인 도구다. **클라이언트 입력에 의존하지 않는 단방향 데이터 생성**이 핵심 메커니즘이다. TCP 버전은 지속적인 스트리밍 테스트에, UDP 버전은 단일 패킷 응답 테스트에 각각 적합하다.

그러나 이 프로토콜은 현대적인 보안 관점에서 **위험 요소**로 간주될 수 있다. 서비스가 가동 중인 경우, 악의적인 클라이언트가 많은 연결을 열어 서버 리소스를 소모시키는 **DDoS 공격의 반사체**로 악용될 가능성이 있다. 또한, 데이터의 내용이 제한되지 않기 때문에 불필요한 대역폭 소비를 초래할 수 있다. 이러한 이유로 현대 시스템에서는 보안을 이유로 CHARGEN 서비스(`포트 19`)를 기본적으로 비활성화하거나 차단하는 것이 일반적이다.

### 정리
Character Generator Protocol(RFC 864)은 네트워크 진단을 위해 설계된 초기 인터넷 프로토콜이다. **포트 19**를 사용하며, TCP는 연결 기반의 지속적 스트리밍을, UDP는 비연결형의 단일 응답을 제공한다. 서버는 클라이언트 입력을 완전히 무시하고 **규칙적인 ASCII 문자 패턴**을 생성하여 보내는 것이 핵심 동작 원리다. 이 단순함은 디버깅과 측정에 유용하지만, 보안 취약점과 남용 가능성으로 인해 오늘날에는 실전 운영 환경보다는 프로토콜 개념 학습과 역사적 맥락에서 주로 다뤄진다.
