> 한 줄 요약: RFC 866은 TCP와 UDP 포트 11에서 동작하는 활성 사용자 서비스의 표준을 정의하며, 서버는 클라이언트의 입력을 무시하고 현재 로그인된 사용자 목록만 응답으로 보낸다.

### 개요
RFC 866은 1983년 5월 J. Postel이 작성한 ARPA 인터넷 커뮤니티 표준으로, Active Users Protocol을 구현하려는 호스트가 따라야 할 규격을 정의한다. 이 서비스는 디버깅과 측정에 유용한 도구로, 입력과 무관하게 호스트에 현재 로그인된 사용자 목록을 보내는 단순한 구조를 가진다. 여기서 활성 사용자란 SYSTAT이나 WHO에 나열되는, 로그인된 사용자를 의미한다.

### 두 가지 전송 방식
RFC 866은 같은 서비스를 TCP와 UDP 위에서 각각 정의한다. 두 방식 모두 포트 11을 사용하며, 서버는 클라이언트가 보낸 데이터를 무시하고 활성 사용자 목록만 응답으로 돌려준다는 공통점을 가진다.

#### TCP 기반 서비스
TCP 기반 서비스는 연결 기반 애플리케이션으로 동작한다. 서버는 TCP 포트 11에서 연결을 기다리며, 연결이 수립되면 현재 활성 사용자 목록을 연결로 보낸다. 이때 연결을 통해 수신된 데이터는 모두 버려진다. 서버는 목록을 보낸 뒤 연결을 닫는다.

#### UDP 기반 서비스
UDP 기반 서비스는 데이터그램 기반 애플리케이션으로 동작한다. 서버는 UDP 포트 11에서 데이터그램을 기다리며, 데이터그램을 수신하면 활성 사용자 목록을 담은 응답 데이터그램을 보낸다. 수신 데이터그램의 내용은 무시된다.

목록이 하나의 데이터그램에 들어가지 않으면 여러 데이터그램으로 나누어 보내지만, 한 사용자의 정보(한 줄)를 데이터그램 경계에서 끊지 않는다. 클라이언트는 모든 데이터그램이 도착할 때까지 타임아웃을 두고 기다려야 하며, 데이터그램이 순서대로 도착한다는 보장은 없다.

### 사용자 목록 문법
사용자 목록에는 특정 문법이 정의되어 있지 않다. 다만 ASCII 인쇄 가능 문자, 공백, 캐리지 리턴, 라인 피드로 제한할 것을 권장하며, 각 사용자는 별도의 줄에 나열되어야 한다.

### 정리
RFC 866은 디버깅과 측정을 위해 호스트의 현재 로그인 사용자 목록을 제공하는 단순한 표준이다. TCP 기반 서비스는 연결 수립 후 목록을 보내고 연결을 닫으며, UDP 기반 서비스는 데이터그램 요청에 목록 데이터그램으로 응답한다. 두 방식 모두 포트 11을 사용하고 입력 데이터를 무시하며, 목록 문법은 엄격하게 규정되지 않아 ASCII 인쇄 문자 위주로 한 줄에 한 사용자를 나열하는 것이 권장된다.
