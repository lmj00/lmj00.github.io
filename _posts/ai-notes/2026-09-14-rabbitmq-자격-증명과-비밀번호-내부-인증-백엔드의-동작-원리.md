> 한 줄 요약: RabbitMQ 내부 인증 백엔드는 비밀번호를 솔트와 결합해 해시로 저장하며, 해시 함수와 자격 증명 검증기를 설정으로 바꿀 수 있다. 비밀번호 없는 사용자는 x509 인증 전용이며, HTTP API나 정의 파일용 해시는 솔트를 두 번 붙여 base64로 인코딩하는 고정 순서로 만든다.

### 개요

RabbitMQ는 여러 인증 메커니즘을 지원하며, 그중 일부는 사용자 이름과 비밀번호 쌍을 사용한다. 이 자격 증명 쌍은 **인증 백엔드**에 전달되고, 백엔드가 실제 인증을 수행한다. RabbitMQ에 기본으로 포함된 **내부(내장) 인증 백엔드**는 RabbitMQ 내부 데이터 저장소에 사용자 자격 증명을 보관하며, `rabbitmqctl`로 새 사용자를 추가할 때 비밀번호를 솔트 값과 결합해 해싱한다. 이 문서의 내용은 이 내부 인증 백엔드를 기준으로 하므로, 다른 인증 백엔드를 사용하면 대부분 적용되지 않는다.

### 비밀번호 해싱: 솔트 결합과 해시 함수 선택

내부 인증 백엔드에서 비밀번호는 솔트 값과 결합된 뒤 해싱된다. RabbitMQ는 사용할 해시 함수를 설정 파일로 바꿀 수 있다. 예를 들어 SHA-512를 사용하려면 다음과 같이 설정한다.

```ini
password_hashing_module = rabbit_password_hashing_sha512
```

기본 제공 해싱 모듈은 세 가지다.

| 모듈 | 역할 |
|---|---|
| `rabbit_password_hashing_sha256` | 기본값 |
| `rabbit_password_hashing_sha512` | SHA-512 사용 |
| `rabbit_password_hashing_md5` | 하위 호환용 |

기본값은 SHA-256이며, 플러그인으로 추가 알고리즘을 제공할 수도 있다. 설정한 알고리즘은 새로 생성되는 사용자나 `rabbitmqctl`로 비밀번호를 변경하는 사용자부터 적용된다. 즉 이미 존재하는 사용자의 해시는 설정 변경만으로 자동 갱신되지 않는다.

### 자격 증명 검증기로 비밀번호 정책 적용

RabbitMQ는 **자격 증명 검증기(credential validator)**를 지원한다. 검증기는 내부 인증 백엔드에서만 동작하며, 새 사용자가 추가되거나 기존 사용자의 비밀번호가 변경될 때 적용된다. 검증기는 검증 함수를 구현하는 모듈이며, 사용할 모듈과 추가 설정을 설정 파일에 지정해야 한다.

기본 제공 검증기는 세 가지다.

- `rabbit_credential_validator_accept_everything`: 모든 값을 조건 없이 수용한다. 하위 호환성을 위해 기본 검증기로 사용된다.
- `rabbit_credential_validator_min_password_length`: 비밀번호 길이를 검증한다.
- `rabbit_credential_validator_password_regexp`: 비밀번호가 정규 표현식과 일치하는지 검증한다. 제한 사항이 있다.

최소 길이 검증기 설정 예시:

```ini
credential_validator.validation_backend = rabbit_credential_validator_min_password_length
credential_validator.min_length = 30
```

정규 표현식 검증기 설정 예시:

```ini
credential_validator.validation_backend = rabbit_credential_validator_password_regexp
credential_validator.regexp = ^[a-bA-Z0-9$]{20,100}
```

#### 검증기 사용 시 한계

검증기에는 설정 파일 문법과 셸 해석 때문에 생기는 제약이 있다. 새 스타일 설정 형식은 `#`를 주석 문자로 사용하므로 정규 표현식 값에 `#`를 쓸 수 없고, 값의 앞뒤 공백은 설정 파서가 제거한다. CLI 도구로 사용자를 관리할 때는 셸 이스케이프 규칙도 고려해야 한다.

#### 커스텀 검증기

모든 검증기는 `rabbit_credential_validator`라는 단일 함수 behaviour를 구현하는 모듈이므로, 플러그인으로 추가 구현을 제공할 수 있다. 검증기는 비밀번호뿐 아니라 사용자 이름을 검증하거나, 사용자 이름과 비밀번호가 동일한지 확인하는 등 다른 로직도 처리할 수 있다.

### 비밀번호 없는 사용자

내부 인증 백엔드는 비밀번호가 없거나 빈 비밀번호를 가진 사용자를 허용한다. 단, 검증기가 이를 허용해야 한다. 이런 **비밀번호 없는 사용자**는 x509 인증서 인증 같은 비밀번호 없는 인증 메커니즘에서만 사용하도록 설계되었다.

비밀번호 없는 사용자는 검증을 통과하는 아무 비밀번호로 사용자를 만든 뒤, `rabbitmqctl`의 `clear_password` 명령으로 비밀번호를 지워 생성한다.

```bash
rabbitmqctl add_user passwordless-user "pa$$wordless"
rabbitmqctl clear_password passwordless-user
# set_permissions로 가상 호스트 접근 권한을 부여하는 것을 잊지 말 것
```

빈 비밀번호로 인증을 시도하면 내부 인증 백엔드가 조건 없이 거부하고, 서버 로그에 특유의 오류 메시지를 남긴다. 빈 비밀번호는 x509 인증서 인증이나 LDAP 같은 외부 서비스 인증에서만 사용할 수 있다.

### x509 인증서 기반 인증

비밀번호를 아예 사용하지 않고 TLS x509 인증서로 인증하도록 구성할 수도 있다. 이때 인증은 TLS **피어 인증서 체인 검증**에 의존하며, 이는 RFC 5280에 기반한다.

구성 순서는 다음과 같다.

1. 비밀번호 없는 사용자를 생성한다.
2. `rabbitmq-auth-mechanism-ssl` 플러그인을 활성화한다.
3. 플러그인의 설정 지침을 따른다.
4. 클라이언트 연결이 TLS와 `EXTERNAL` 인증 메커니즘을 사용하도록 설정한다.
5. 클라이언트가 인증서/키 쌍과 CA 인증서(또는 인증서 체인)를 제공하도록 설정한다. 서버는 이 체인을 검증하므로, 체인에 포함된 인증서 중 적어도 하나는 대상 노드가 신뢰해야 한다.

### 비밀번호 해시 계산하기

HTTP API로 사용자 정보를 업데이트하거나 가져올 정의 파일(definition file)을 생성할 때는 비밀번호 해시를 직접 계산해야 할 수 있다. 해시는 `rabbitmqctl`, `rabbitmqadmin`, HTTP API 세 가지 방법으로 얻을 수 있다.

`rabbitmqctl` 사용 예:

```bash
rabbitmqctl hash_password foobarbaz
# 출력 예: 27cx5+wEi8R8uwTeTr3hk5azuV3yYxxAtwPPhCyrbdsxVhqq
```

`rabbitmqadmin` 사용 예:

```bash
rabbitmqadmin passwords salt_and_hash foobarbaz
```

HTTP API 사용 예:

```bash
curl -4su guest:guest -X GET localhost:15672/api/auth/hash_password/foobarbaz
# 출력 예: {"ok":"TBybOvomyVw6BqBU/fHCEpVhDO7fLdQ4kxZDUpt6hagCxV8I"}
```

#### 해시 계산 알고리즘

해시는 다음 순서로 계산된다. RabbitMQ는 사용자를 생성하거나 업데이트할 때마다 랜덤 솔트를 새로 생성한다.

![diagram](/assets/diagrams/2026-09-14-rabbitmq-자격-증명과-비밀번호-내부-인증-백엔드의-동작-원리-1.svg)

예를 들어 비밀번호가 `test12`이고 기본 해시 함수인 SHA-256을 사용한다고 하자. 먼저 32비트 랜덤 솔트가 생성되는데, 문서의 예에서는 `908D C60A`다. 솔트를 비밀번호의 UTF-8 표현 앞에 붙이면 `908D C60A 7465 7374 3132`가 되고, 이를 SHA-256으로 해싱한 뒤 해시 값 앞에 솔트를 다시 붙인다. 마지막으로 base64 인코딩을 적용하면 `kI3GCqW5JLMJa4iX1lo7X4D6XbYqlLgxIs30+P6tENUV2POR`가 된다. 이 base64 값이 HTTP API 요청과 정의 파일의 `password_hash` 값으로 사용된다.

### 정리

RabbitMQ 내부 인증 백엔드는 새 사용자를 추가할 때 비밀번호를 랜덤 솔트와 결합해 해싱하며, 기본 해시 함수는 SHA-256이고 SHA-512 또는 하위 호환용 MD5로 교체할 수 있다. 자격 증명 검증기는 사용자 생성과 비밀번호 변경 시점에만 적용되며, 기본값은 모든 값을 수용하는 `accept_everything`이다. 비밀번호 없는 사용자는 x509 인증 같은 비밀번호 없는 메커니즘 전용이며, 내부 백엔드는 빈 비밀번호로 직접 인증하는 시도를 거부한다. HTTP API나 정의 파일용 해시는 32비트 랜덤 솔트를 비밀번호 앞에 붙여 해싱하고, 그 해시 앞에 같은 솔트를 다시 붙인 뒤 base64로 인코딩하는 고정된 순서로 만든다.
